# 反馈到多类候选：选型、接口与实施

分支：`codex/feedback-candidates`；使用现有反馈、独立评测、审查及发布治理接口。

## 技术选型与接口

沿用明确授权的开发集和原文引用校验；新 Skill 使用既有提案器，其他工件使用有请求预算的 HTTP 反思模型生成完整替换文本。统一入口支持 `system_prompt`、`skill_description`、`skill_body`、`new_skill`，冻结反馈、目标版本及配置。每个候选必须经过静态门，生成不等于授权发布。

## 实施与验收

1. 校验反馈授权、引用、工件类型、可修改目标和执行计划。
2. 实现生成、失败记录和静态门，连接现有独立开发/选择评测、人工审查、版本发布与回滚。
3. 单元及集成测试覆盖四类候选、授权撤回/篡改、预算、静态拒绝、独立数据隔离和发布回滚。
4. 在隔离环境演练端到端链路，区分合成夹具与实际模型结果；最终只发布验收通过的集成版本。
