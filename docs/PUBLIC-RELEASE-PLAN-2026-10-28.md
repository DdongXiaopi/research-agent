# GitHub 公开发布完善计划（2026-10-28）

目标：公开一个可安装、可运行、功能边界准确、证据可复核的 RSI 项目。执行时保留现有研究工作区和历史 Git 仓库；公开版本通过明确的文件清单生成，避免把临时资料混入提交。

## 执行原则

- 每一步记录实际结果、验证方式和未解决项；不能把历史测试结果写成当前验证。
- 不删除本地实验资料，不将 `.env`、个人记忆、模型原始响应或本机路径纳入公开版本。
- 项目自有代码使用用户选定的 MIT 许可证。第三方代码、数据和模型输出继续遵循各自许可与访问条件；未核清的内容不进入公开文件清单。
- 正式发布前从公开清单创建全新目录，检查其中的文件、文档链接和离线主流程。

## 1. 公开文件清单与仓库卫生

工作：盘点已跟踪和未跟踪的源码、配置、数据、产物；建立明确的公开清单与排除规则；生成独立公开快照。检查潜在凭据、个人记录、模型响应和绝对本机路径。历史仓库保留为本地研究仓库。

验收：快照仅含允许公开的文件；全新目录中没有 `.workbuddy`、`.env`、缓存、原始请求/响应及临时目录；清单可重复生成。

## 2. 项目及第三方许可

工作：添加根目录 MIT `LICENSE`；核对公开快照中实际包含的第三方代码、数据和依赖；更新 `THIRD_PARTY.yml` 与再分发说明。把无法确认许可的材料排除。

验收：公开文件按自有代码、第三方代码、数据和生成产物分类；每类都有许可或明确的排除决定。

## 3. 复现材料与文档路径

工作：清点 README、状态和实验报告指向的本地 `.workbuddy` 路径；公开可分发的预注册、聚合摘要、校验脚本和来源清单；无法公开的原始材料改为明确的复现边界。

验收：公开文档中的本地链接均可解析；声称可运行的复核命令在公开快照中具备输入；不可公开的材料不再被描述为公开可复核。

## 4. 主流程和命令入口

工作：写清 `rsi.py`、`research_assistant.py`、`ai_grounding.py` 的职责和产物交接；提供一条离线闭环示例。仅当确有重复参数或断开的产物交接时添加统一入口。

验收：新用户能从 README 进入一条不需模型凭据的最小闭环；每个步骤的输入、输出和下一步明确。

## 5. 功能范围与停用入口

工作：盘点 CLI 和公开文档中的命令，逐项标记为支持、受限或停用。对 `multiseed`、`ablate` 和 paper-qa 文档级适配作出明确决定；超出范围的能力不在公开功能表中承诺。

验收：命令帮助、README 和实际代码行为一致；没有“显示可用但执行时仅返回未实现”的常规命令。

## 6. 安装与持续检查

工作：整理 Python 3.12 最小依赖、可选优化器及 Pi bridge 依赖；增加 GitHub Actions 的离线安装、smoke、CLI 和公开文件清单检查。检查在无历史产物、无模型密钥的环境中可运行。

验收：公开快照可以在支持的平台完成离线安装和主流程 smoke；自动检查不访问付费模型或私有数据。

## 7. 对外声明

工作：统一 README、项目简介和状态文件的能力与实验边界；区分工程可运行、科研效果未过门和未支持功能；移除失效链接与过期当前结论。

验收：每项公开能力有入口、运行条件和可核查证据；性能与自进化收益不超出当前实测结论。

### 2026-10-28 复核修复

- 原快照校验信任清单路径，且 CI 在清单缺失时跳过；现改用独立白名单、必需文件和 Git 跟踪集合校验，并让 CI 必须执行。
- 原公开文档只有历史结论描述，缺可分享的来源与结果身份；现提供聚合证据及可选私有原件核验，保留不能独立重跑原始实验的明确边界。
- 原科研流程 smoke 止于回答；现延伸到经同意的合成开发反馈和候选计划。所有合成资料都在临时目录销毁，不成为科研证据。
- 固定任务 `rsi e2e` 原先要求本地 LitQA2 数据；新增一次性合成题目与冻结 split 夹具，能在公开仓库内验证评测、审查和回滚的交接，且不把合成题目写入仓库。
- 原 paper-qa 入口先提示安装依赖，之后仍抛未实现错误；现直接说明真实状态和可用替代入口。

### 2026-10-28 必修项与后续迭代裁定

- **公开发布前必修，已本地修复**：公开仓库的默认测试必须不依赖排除在快照外的历史数据/vendor/收据；公开快照仅分发自包含测试，CI 跑全部随包测试。`make_splits.py` 接受用户提供的合法 Parquet 路径、缺文件立即非零退出；数据依赖单独列在 `requirements-data.txt`，`smoke_data_preparation.py` 用一次性合成 Parquet 验证准备→冻结→基线→轮次→审查→回滚。`bootstrap_project.py` 的恢复与安装顺序在开始文档给出，Pi 可单独安装。开放研究计划的示例和 CI 将产物写入隔离的 `RSI_HOME`，避免污染待校验的公开快照。
- **保留限制，后续按需实现**：`rsi ablate`、旧 `multiseed` 入口、paper-qa 文档网关、完整正向 task-input 四工件公开验收、迁移报告 `smoke` 角色修正。这些不在当前零数据公开主流程中承诺为已完成。task-input 协议指纹仍绑定未分发的历史 manifest/vendor；修改它需要新协议身份，不能为了让一个测试通过而静默删去绑定。
- **科研效度门不得视为软件修复项**：G05/G06/G09 校准和完整 claim 指标、候选增益、当前协议三轮及消融证据均保留受限状态。未来新数据和新协议可重新评估，不降低既定门槛，不复用已曝光终评题。

### 2026-10-29 接口复核修复

依据 [数据与执行接口修复计划](PROJECT-REPAIR-PLAN-2026-10-29.md)，数据准备统一预检所有输入并暂存产物；重复题目 ID 被拒绝，中途提交失败会恢复已有文件。冻结操作在成功返回前核对封存文件与自身完整性。开放科研 CLI 的每个 `--execute` 入口要求调用方提供匹配的计划哈希。原始 LitQA2/ProtocolQA 在隔离副本准备、冻结、校验通过；人工标注、科研效度门和远端 GitHub Actions 状态未因此改变。
